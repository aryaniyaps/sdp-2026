\chapter{\uppercase{Implementation}}
\label{ch:impl}
This chapter covers the tools we used, the six main algorithms (with the Maya example
walked through each) and how the engine plugs into Pi.

\section{\uppercase{Implementation Environment}}
The memory service is written in Rust, using Tokio for the background workers, Axum
for the API and SQLx for PostgreSQL. PostgreSQL 17 with pgvector is the main store and
does both full-text and vector search, and Neo4j 5.26 holds the graph copy. The models
run locally on Ollama: our fine-tuned Qwen3-4B-Instruct-2507 extracts assertions, combines
them into inferences and writes cited answers, and Qwen3-Embedding-0.6B makes the
vectors. The dashboard is React + TypeScript. Training used Python, PyTorch, Transformers,
PEFT and bitsandbytes, with llama.cpp to make the GGUF, and Docker Compose runs the services.

\section{\uppercase{Algorithms}}
Context selection is in M2, entity resolution and versioning in M3, consolidation and
invalidation is split between M2 and M3, and retrieval, rank fusion and answer generation
are in M4.

\subsection{Priority-Based Context Selection}
\label{sec:alg-context}
The extractor needs to see the assertions already stored about the same people, or it
can't tell a repeat from a correction, but they may not all fit its input limit
(Algorithm~\ref{alg:context}). When E3 arrives Maya has four stored assertions; if only three fit, the
home city one ranks first because E3 mentions both Maya and Chennai, and the rest follow
by recency.

\begin{algorithm}[!htbp]
\caption{Priority-based context selection}
\label{alg:context}
\begin{pseudo}
IF all existing assertions fit: RETURN all of them
Score assertions by subject and value mentions in new messages
Rank stronger matches first; break ties by recency
Binary search for the largest ranked prefix that fits
RETURN the selected assertions in their original order
\end{pseudo}
\end{algorithm}

\subsection{Entity Resolution and Memory Versioning}
The key rule is that a conflicting value never silently overwrites the old one, and the
old assertion is superseded, not deleted (Algorithm~\ref{alg:versioning}). The E3 claim (home city
Bengaluru, correction, confidence 0.95) conflicts with R1 Chennai and $0.95 \geq 0.8$, so R1 is
superseded with validity 1--10 October and R2 Bengaluru becomes active.

\begin{algorithm}[!htbp]
\caption{Entity resolution and memory versioning}
\label{alg:versioning}
\begin{pseudo}
Match entity by type and normalised name or alias; else create it
IF the same assertion exists: attach the new source quote
ELSE IF no conflicting single-value assertion: store as active
ELSE IF explicit correction AND confidence >= 0.8:
    Supersede the old assertion; activate the new one
ELSE: mark both values as disputed
\end{pseudo}
\end{algorithm}

\subsection{Memory Consolidation and Invalidation}
The model proposes an inference but the code decides whether to save it
(Algorithm~\ref{alg:consolidation}). For Maya, A1 (NovaTech), A2 (software engineer) and A3 (remote)
give inference I1. If A3 were retracted later, I1 would be marked stale.

\begin{algorithm}[!htbp]
\caption{Memory consolidation and invalidation}
\label{alg:consolidation}
\begin{pseudo}
Ask the model to combine related active assertions into inferences
Require >= 2 distinct supports; check support IDs and subject
Recheck that the supports are still active, then save with links
WHEN a support changes: mark dependent inferences stale (recursively)
\end{pseudo}
\end{algorithm}

\subsection{Hybrid Retrieval and Graph Traversal}
This returns separate ranked lists, and the graph expansion stops after two rounds so it
doesn't pull in the whole graph (Algorithm~\ref{alg:retrieval}). For E5, keyword and vector search find
R2 and the work assertions, and the \code{supersedes} link of R2 reaches R1 (Chennai).

\begin{algorithm}[!htbp]
\caption{Hybrid retrieval and graph traversal}
\label{alg:retrieval}
\begin{pseudo}
Resolve date phrases; run keyword and vector search
Add time-based candidates when there is a date window
Expand from matching assertions and entities for two rounds
Filter by validity and distance; RETURN the candidate lists
\end{pseudo}
\end{algorithm}

\subsection{Reciprocal Rank Fusion and Context Packing}
Scores from different searches can't be compared, so only ranks are used
(Algorithm~\ref{alg:rrf}). If R2 is first and R1 second in all three lists, R2 scores
$3/61 \approx 0.0492$ and R1 $3/62 \approx 0.0484$, and both fit easily in Pi's 2,048 tokens.

\begin{algorithm}[!htbp]
\caption{Reciprocal Rank Fusion and context packing}
\label{alg:rrf}
\begin{pseudo}
Score(memory) = SUM over lists of 1 / (60 + rank)
Sort by score; break ties by memory ID
Add each memory with its source quotes if it fits the budget
Stop at top_k memories; RETURN the packed context
\end{pseudo}
\end{algorithm}

\subsection{Source-Grounded Answer Generation}
Bad output is rejected rather than patched, so every citation the user sees points to a
memory that was actually retrieved (Algorithm~\ref{alg:answer}). For E5 the answer cites R2 for
Bengaluru and R1 for Chennai, so it passes.

\begin{algorithm}[!htbp]
\caption{Source-grounded answer generation}
\label{alg:answer}
\begin{pseudo}
IF nothing was retrieved: RETURN "Insufficient evidence."
Ask the model to answer only from the retrieved memories
Allow only retrieved IDs as citations; check the format
Require citations when the answer claims enough evidence
\end{pseudo}
\end{algorithm}

\section{\uppercase{Integration with the Pi Agent}}
Pi's memory client saves every message with a namespace and session. When Maya asks
E5, Pi sends a recall request for \code{user:maya} (\code{top\_k} 10, \code{max\_tokens} 2,048), and the
result is added to the prompt only if it is non-empty and from the same namespace.
