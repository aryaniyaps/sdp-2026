\section{\uppercase{M1: Source Storage and the Job Queue}}
\label{sec:m1-impl}
The service runs its schema migrations at start-up and enables \code{vector} and \code{pgcrypto}.
Appendix~\ref{app:schema} lists the tables. Chunks and assertions have a generated
\code{tsvector} column with a GIN index \cite{postgres2026fts} and a \code{vector(1024)} column
with an HNSW cosine index \cite{kane2026pgvector}.

The retain handler accepts up to 1,000 events per batch. It locks the namespace and hashes the
request. A known \code{external\_id} with the same hash returns the stored IDs; a different hash is
rejected as a conflict. Otherwise the episode, events, chunks and extract job are saved in one
transaction. Embeddings come from Ollama, and the model is warmed up at start-up so the first
recall doesn't wait. Each job has a \code{dedupe\_key} such as \code{extract:EP2}, so it is never
queued twice. A worker leases the namespace for 15 minutes and renews it while working.

The extractor must see stored assertions about the same people to tell a repeat from a
correction. When they don't all fit, Algorithm~\ref{alg:context} keeps the most relevant.

\begin{algorithm}[!htbp]
\caption{Priority-based context selection}
\label{alg:context}
\begin{algorithmic}[1]
\State $T \gets \min(\mathit{budget} - \mathit{reserve},\ 6000)$
\If{the prompt with all assertions has at most $T$ tokens}
  \State \Return all assertions
\EndIf
\For{each stored assertion $a$}
  \State $s(a) \gets 3$ if its subject is in the new events, plus $2$ if its value is too
\EndFor
\State Sort the assertions by $s(a)$, highest first; ties stay newest first
\State Binary search for the largest $n$ whose first $n$ assertions fit in $T$
\State \Return those $n$ assertions in their original order
\end{algorithmic}
\end{algorithm}

For E3, Maya's five assertions all fit, so all are sent; the model needs R1 to see that
Bengaluru is a correction. Each reply is checked against the claim schema, and every quote must
be an exact substring of its event. A failed check gets a repair prompt, at most three replies in
total. Claims that look like passwords or keys are dropped.

The model proposes inferences, but code decides whether to save them
(Algorithm~\ref{alg:consolidation}). For Maya, A1 to A3 give I1. If A3 were retracted, I1 would
become stale.

\begin{algorithm}[!htbp]
\caption{Memory consolidation and invalidation}
\label{alg:consolidation}
\begin{algorithmic}[1]
\State Ask the model to combine related active assertions into inferences
\For{each proposed inference $i$}
  \If{$i$ has fewer than 2 distinct supports, or a support is unknown or from another subject}
    \State Reject $i$
  \ElsIf{all supports are still active}
    \State Save $i$ and one \code{supports} edge to each support
  \EndIf
\EndFor
\State \textbf{When} a support is superseded or retracted: mark every inference built on it \code{stale}
\end{algorithmic}
\end{algorithm}

\section{\uppercase{M3: Versioning and the Knowledge Graph}}
\label{sec:m3-impl}
A conflicting value never overwrites the old one (Algorithm~\ref{alg:versioning}). The slot key
is \code{<entity id>::<normalised predicate>}, and a partial unique index allows one active
single-valued assertion per slot, so even a bug can't leave two current home cities. Every change
gets a new \emph{revision} number.

\begin{algorithm}[!htbp]
\caption{Entity resolution and memory versioning}
\label{alg:versioning}
\begin{algorithmic}[1]
\State Find the entity by type and normalised name or alias; create it if none matches
\State $\mathit{slot} \gets$ entity id $+$ normalised predicate
\If{an assertion in $\mathit{slot}$ has the same value}
  \State Add the new source quote to it
\ElsIf{$\mathit{slot}$ has no active single-valued assertion}
  \State Save the claim as a new active assertion
\ElsIf{the claim is a correction \textbf{and} confidence $\geq 0.8$}
  \State Set the old assertion to \code{superseded} with $\mathit{valid\_to} \gets$ the new $\mathit{valid\_from}$
  \State Save the new assertion as active, with a \code{supersedes} edge to the old one
\Else
  \State Mark both assertions \code{contested}
\EndIf
\State Queue a \code{project} job for every assertion that changed
\end{algorithmic}
\end{algorithm}

Neo4j runs with a 512\,MB page cache and up to 1\,GB heap, accessed over HTTP
\cite{neo4j2026http}. The graph is a copy that can always be rebuilt from PostgreSQL. The
projection worker \code{MERGE}s each assertion, its entities and its edges, but only if the job's
revision is not older than the stored one. A late job therefore never takes the graph back in
time. A rebuild job raises a minimum revision, deletes older nodes and projects everything again.

Each channel returns up to 40 results (Algorithm~\ref{alg:retrieval}). The graph expands two
rounds from up to 20 seeds. Graph hits are re-checked in PostgreSQL, since the copy may lag.

\begin{algorithm}[!htbp]
\caption{Hybrid retrieval and graph traversal}
\label{alg:retrieval}
\begin{algorithmic}[1]
\State Turn date phrases in the query into a date window, if there are any
\State $L_{kw} \gets$ keyword search over assertions and chunks
\State $L_{vec} \gets$ vector search over assertions and chunks
\If{a date window or \code{as\_of} is given}
  \State $L_{time} \gets$ assertions in the window, newest first
\EndIf
\State $\mathit{seeds} \gets$ top 5 of $L_{kw}$ $\cup$ top 5 of $L_{vec}$ $\cup$ entities in the query
\State $L_{graph} \gets$ neighbours of $\mathit{seeds}$ in Neo4j, two rounds
\State Remove graph hits that fail the PostgreSQL status and date filter
\State \Return $L_{kw}, L_{vec}, L_{time}, L_{graph}$
\end{algorithmic}
\end{algorithm}

Channel scores can't be compared, so Reciprocal Rank Fusion \cite{cormack2009rrf} uses ranks:
\begin{equation}
\label{eq:rrf}
\mathit{RRF}(d) = \sum_{L \,\ni\, d} \frac{1}{k + \mathit{rank}_L(d)}, \qquad k = 60.
\end{equation}
Algorithm~\ref{alg:rrf} then packs the results into the budget.

\begin{algorithm}[!htbp]
\caption{Reciprocal Rank Fusion and context packing}
\label{alg:rrf}
\begin{algorithmic}[1]
\State Score every memory $d$ with Equation~\eqref{eq:rrf}; sort highest first, ties by ID
\If{\code{include\_raw}}
  \State Alternate source chunks and assertions, each in score order
\EndIf
\For{each memory $d$ in this order, until $\mathit{top\_k}$ are added}
  \If{$d$ with its quotes fits in the remaining budget}
    \State Add $d$ and up to 3 quotes of at most 1,200 characters each
  \EndIf
\EndFor
\State \Return the packed context text
\end{algorithmic}
\end{algorithm}

Pi receives each memory with its status, dates and source quote:
\begin{datablock}
[C1] My name is Maya. I live in Chennai. I work as ...
[R2] Maya's home city is Bengaluru. [attribute; active; from 2026-10-10]
  Source (S2, user): Bengaluru is now my home city.

\end{datablock}
So the agent can answer: Bengaluru since 10 October, Chennai before, remote engineer at
NovaTech. A reflect answer would cite R2 and C1.
\end{maya}

The optional reflect endpoint answers from the recall result (Algorithm~\ref{alg:answer}). Bad
output is rejected, not repaired, so every citation points to a retrieved memory.

\begin{algorithm}[!htbp]
\caption{Source-grounded answer generation}
\label{alg:answer}
\begin{algorithmic}[1]
\State Run recall for the question
\If{recall returned nothing}
  \State \Return ``Insufficient evidence.''
\EndIf
\State Ask the model to answer only from the recalled memories, citing their IDs
\If{a citation is not a recalled ID, the format is wrong, or nothing is cited}
  \State Reject the answer
\EndIf
\State \Return the answer with its citations
\end{algorithmic}
\end{algorithm}

\section{\uppercase{Integration with the Pi Agent}}
Our Pi extension saves every message under a namespace (from \code{MEMORY\_NAMESPACE} or the
project folder). The \code{external\_id} marks tool results, conversation branches and explicit
``remember this'' requests. Before each answer Pi calls recall and adds a non-empty result from
the same namespace to the prompt.
