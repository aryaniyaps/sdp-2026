\chapter{\uppercase{Results, Performance Analysis and Comparison}}
\label{ch:results}
This chapter covers the training data, the model, a live demo, the benchmark and a comparison
with published systems.

\section{\uppercase{Datasets}}
Each training row is a short conversation plus a task (extract, consolidate or reflect) and the
expected memory, with every item tied to a source quote. All data is synthetic. The teacher
model GPT-5.6-sol wrote and labelled conversations in 16 domains, such as family, travel, work
and software, and a second model cross-checked the labels. This gave 2,961 rows, split
2,095 / 424 / 442. Many rows check that only what the user said is stored: if the assistant
suggests violin and the user says they are learning watercolor, only watercolor is stored.

Our first benchmark runs showed that most episodes expected only two or three claims, so the
model learned to stop early. We added 480 casual two-person conversations in which Claude
Sonnet 5.5 labelled every fact (5,284 claims), plus 600 older rows so other tasks were not
forgotten: 1,719 training and 670 validation rows. None of the data uses LoCoMo text.

\section{\uppercase{Fine-Tuning and Model Selection}}
Qwen3-1.7B passed only 18 of 33 real conversation windows, with wrong quotes, speakers and
IDs. We moved to Qwen3-4B-Instruct-2507 and trained it with QLoRA in Stages A and B
(\code{general-v1}). Stage C continued for one epoch on the new data with rows up to 6,144
tokens. It took 2.9 hours on the 8 GB RTX 4070 (peak 7.3 GB, validation loss 0.155). We fixed
the rule in advance: use \code{general-v2} if it matches v1 on the two development
conversations. It did, so v2 was used for the test.

\section{\uppercase{Benchmark Setup}}
\label{sec:setup}
We used LoCoMo \cite{maharana2024locomo}, on which the Mem0 paper \cite{chhikara2025mem0}
reports Mem0, Zep and A-Mem. It has ten long two-person conversations (272 sessions) and 1,540
questions in four categories; like Mem0, we left out the adversarial category. Each
conversation is ingested as its own memory bank. The reader, Claude Haiku 5.5 in the Pi agent
with Mem0's answer prompt, gets one of five contexts:
\begin{itemize}[itemsep=0pt]
\item \textbf{Memory engine:} our recall, up to 8,192 tokens.
\item \textbf{Plain retrieval:} keyword and vector search over raw text, same budget.
\item \textbf{Recent window:} the last 8,192 tokens of the conversation.
\item \textbf{Whole conversation} (upper reference) and \textbf{no memory}.
\end{itemize}
Ablations removed the source text, the graph or consolidation, on 300 questions (75 per
category). Two blind judges grade answers with Mem0's rubric: TypeSafe Jev
\cite{typesafe2026jev} (correct if $p \geq 0.5$) and GPT-4o-mini. We report paired bootstrap 95\%
intervals \cite{efron1993bootstrap} and Cohen's kappa \cite{cohen1960kappa}. Conditions and pass
marks were committed before the run, and we debugged only on two conversations. The full run
(\code{benchmark/overnight.sh}) took 7 h 45 min, and a notebook recomputes every number from
the saved records.

Early dev runs found several bugs. For example, ``yesterday'' was stored as the day it was
said, consolidation prompts grew too long and real corrections were thrown away. Each fix is
logged in \code{iterations.json} in the \code{benchmark} folder. Recall of
assertions alone scored 45.9\% against 79.8\% for plain retrieval because the extractor missed
facts. Mixing in source text gave 82.8\% against 82.4\%.

\section{\uppercase{Results}}
\label{sec:results}
With the engine the reader got 83.1\% right (Table~\ref{tab:bench-main}). No memory gave 0.3\%,
the recent window 43.0\%, plain retrieval 80.0\% and the whole conversation 89.0\%. The engine
closes about a third of the gap to the whole conversation with 30\% of its tokens, and met every
pass mark. The two judges agree on 96.7\% of answers (kappa 0.93). On the eight conversations we
never debugged on, the engine scored 83.0\% against 79.4\%. Over three repeats the standard
deviation was 0.5 points for the engine and 1.3 for plain retrieval.

Most of the gain is on multi-hop questions, 83.0\% against 74.5\%
(Table~\ref{tab:bench-categories}). For ``What subject have Caroline and Melanie both
painted?'', plain retrieval led to ``Nature''. The engine recalled one short assertion per
person, and the reader answered ``Sunsets''. One assertion sums up several turns, so more facts
fit in the budget. Temporal questions were level (80.1\% against 80.4\%).

In the ablations, removing source text cost 9.7 points, because the extractor still misses
facts. Removing the graph or consolidation made no measurable difference; LoCoMo rarely needs
a chain of relations.

\section{\uppercase{Performance Analysis}}
\label{sec:performance}
The engine's context contained the answering turn for 84.4\% of questions, against 80.6\% for
plain retrieval. All 99,971 returned quotes matched the source exactly. The engine sends 6,790
context tokens per question against 22,400 for the whole conversation (14,900 against 35,300
in total), and its context stays under 8,192 however long the history grows. Median answer
time is 5.2 s against 5.5 s, and recall takes 428 ms (p95 584 ms). Building memory for 272
sessions took 4.2 hours, about 56 s per session, almost all extraction. It runs in the
background, so answers don't wait.

\section{\uppercase{Property Tests}}
\label{sec:properties}
LoCoMo can't check whether an old value survives a correction, so 40 scripted conversations
test the stored state directly. The engine refused to answer without evidence in all 6 cases
and never stored an API key. After all 12 updates it returned the new value, and \code{as\_of}
recall returned the old one. The tests also found that none of 12 relative dates was resolved:
the model wrote the date into the sentence but left the field empty, so the send time was used.
After the fix (commit \code{bd76df3}) all 10 extracted events had the right date. The LoCoMo
numbers are from before this fix.

\section{\uppercase{Comparison with Existing Systems}}
\label{sec:comparison}
Table~\ref{tab:bench-published} sets our result beside the Mem0 paper's
\cite{chhikara2025mem0}, which also covers Zep \cite{rasmussen2025zep}, LangMem
\cite{langchain2025langmem} and A-Mem \cite{xu2025amem}. They used GPT-4o-mini as the reader, so
raw scores differ (our whole conversation scores 88.8\%, theirs 72.9\%). The fairer measure is the
gap to the whole conversation in each study: 5.6 points for us, 4.5 for Mem0 with a graph, 6.0
for Mem0 and 6.9 for Zep. We are in the same range, not ahead, and use more context tokens.
Unlike Mem0 and A-Mem, we keep every version with dates and quotes, and everything runs on one
laptop with a 4B model.
