\chapter{\uppercase{System Design}}
\label{ch:design}
This chapter describes the design requirements, the architecture and the five modules,
following the Maya example through them.

\section{\uppercase{Design Requirements}}
We worked from a few rules. Original messages are saved exactly as sent \emph{before}
any extraction, which runs later as a queued job, so a failed model call can't lose a
conversation. A changed assertion becomes a new version and the old value is kept with its
validity interval. Every assertion links to an exact source quote. All data belongs to a
namespace (e.g.\ \code{user:maya}), whatever we hand to a model has to fit a token budget,
and models run locally on Ollama. Neo4j is only a copy that can be rebuilt from PostgreSQL.

\section{\uppercase{Overall Architecture}}
Figure~\ref{fig:architecture} shows the architecture. The client is the Pi coding agent, whose memory
client saves every message through the memory service and asks for recall before
answering. The service is a Rust application with API handlers and background workers.
PostgreSQL with pgvector is the main store for M1 to M4: source events and chunks,
entities, assertions, quotes, vectors and the job queue. Ollama runs our fine-tuned worker
model and a Qwen3 embedding model. Neo4j keeps a graph copy of assertions and entities,
and M4 rechecks every graph hit against PostgreSQL. M5 runs offline, and live chats are
\emph{not} used as training data.

\section{\uppercase{M1 Source Acquisition and Processing}}
M1 saves the source events before anything else (Figure~\ref{fig:m1}). For Maya, the 10 October
conversation arrives as a retain request with namespace \code{user:maya}, session S2 and the
events E3 (her message) and E4 (the agent's reply). The batch is first written to a local
spool so nothing is lost if the service is down, and then sent to \code{POST /api/v2/retain}.
If the same key arrives again with the same hash the existing IDs are returned, so retries
don't create duplicates. The episode, events, chunks and a pending extraction job are
saved in one transaction, and each chunk is embedded into a 1,024-dimensional vector.
Background workers lease a namespace for 15 minutes and retry a job up to 5 times.

\section{\uppercase{M2 Knowledge Extraction and Consolidation}}
M2 has two stages, both using our local model through Ollama (Figure~\ref{fig:m2}).
\textbf{Extraction:} the prompt builder fits the new events and the relevant existing
assertions into the model's input (Section~\ref{sec:alg-context}). For Maya, ``Maya / Chennai'' is shown
next to E3, and the model returns home city Bengaluru, flagged as a correction, with an
exact quote. Output that fails the schema or quotes text that isn't in the source is
retried up to two times. Secrets are filtered out before the claim goes to M3.
\textbf{Consolidation:} after M3 commits, the model may combine two or more active
assertions about the same subject into one inference. Maya's three work assertions become
``Maya works remotely as a software engineer at NovaTech.''

\section{\uppercase{M3 Temporal Knowledge and Graph Management}}
M3 is the only module that writes assertions, inside one PostgreSQL transaction that
holds a namespace lock (Figure~\ref{fig:m3}). It first resolves the entity (Maya). If the same value
already exists it is reinforced, and if the slot is empty a new assertion is made. If a
single-valued slot gets a different value and the claim is a reviewed correction with
confidence at least 0.8, the old assertion is superseded; otherwise both are marked
contested. So R1 Chennai becomes valid from 1 to 10 October and superseded, and R2
Bengaluru is active from 10 October with the E3 quote. A projection worker then copies
the change to Neo4j \cite{neo4j2026http}, checking revisions so an old one can't overwrite a newer one.

\section{\uppercase{M4 Hybrid Retrieval and Grounded Reasoning}}
M4 answers recall requests (Figure~\ref{fig:m4}). On 13 October Pi sends E5 for \code{user:maya} with
\code{top\_k} 10, a maximum distance of 0.45 and a 2,048 token budget. The query goes to
keyword, vector and (with a date window) time-based search, the top results seed a Neo4j
expansion, and the lists are merged with Reciprocal Rank Fusion and packed into the
budget with source quotes. An optional reflect endpoint writes a cited answer.

\section{\uppercase{M5 Model Training and Evaluation}}
M5 runs offline and produces the worker model used by M2 and M4 (Figure~\ref{fig:m5}). A
generator makes short episodes across 16 domains, a teacher model labels them, and the
checked labels are used to train the model with QLoRA, which is then evaluated and
imported into Ollama (details in Chapter~\ref{ch:results}). In the end, when Maya asks E5, Pi answers ``You
now live in Bengaluru, following your move on 10 October 2026. Before that, you lived in
Chennai. You work remotely as a software engineer at NovaTech.''
