Version chains

Every claim keeps its history. When a fact changes the earlier version is closed, not overwritten. It keeps its validity window, its source quote, and a supersedes edge to the version that replaced it.

Retrieval

Lexical and semantic candidates are fetched in parallel, then fused by reciprocal rank. Only versions still live at query time are eligible, so a superseded fact can never come back as current.

Pipeline

Every ingestion and every query writes a durable trace. Each stage records its status, its duration, and the model that ran it.

Ingest text

Run the write path live: extract typed memories, canonicalise them, embed them, and resolve them against what is already stored. Contradicting a stored fact opens a new version and supersedes the old one.
