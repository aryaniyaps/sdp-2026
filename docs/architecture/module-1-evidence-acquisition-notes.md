# Module 1: source audit

Verified against the current working tree on 13 October 2026. This diagram describes logical components of the existing Pi client and Rust service, not additional deployed services. The overall architecture is untouched.

## Source mapping

- `integrations/pi/extension.ts`, `retainBranch`, `agent_settled`: reads the current branch after its namespace cursor, selects user/assistant messages and eligible tool results, takes the last 1,000 events, and constructs a branch-keyed batch. It skips assistant errors and memory-tool results. The namespace cursor advances only after durable enqueue.
- `integrations/pi/spool.ts`, `EvidenceSpool`: writes restrictive-permission JSON files through temporary file, file fsync, rename and directory fsync. Flush retains failed files and removes successfully delivered ones. Delivery retry reuses the batch and external ID. This does not imply chronological ordering across different spool files: flush sorts hashed filenames.
- `integrations/pi/client.ts`, `MemoryClient.flush`: sends the saved request to `/api/v2/retain`; a successful response releases the local spool file.
- `src/knowledge.rs`, `RetainRequest` / `EvidenceEvent`: request fields and typed event timestamps.
- `src/knowledge_store/evidence.rs`, `Store::retain`: validates identifiers, event count, supported roles and UTF-8 content byte length; computes a serialized-request hash; locks the namespace; checks `(namespace, external_id)`; and atomically stores the session, episode, events, full-message chunks, ordered episode-source links and extract job. A changed request with the same key conflicts. Exact replay returns existing episode/job IDs with `created:false`.
- `src/v2/mod.rs`, `retain`: HTTP 200 returns episode ID, job ID and created flag after the durable transaction. A newly created episode starts an independent embedding task under a two-permit semaphore. Neither extraction nor successful embedding is required for acknowledgment.
- `src/lib.rs`, `AppError`: validation errors map to HTTP 400 and conflicts to HTTP 409. Malformed request deserialization can fail at the framework boundary before store validation.
- `migrations/0005_chunk_retrieval.sql`: PostgreSQL-generated English text search and 1,024-dimensional source chunk vectors. One chunk currently contains an entire event; token windowing belongs to downstream extraction.
- `src/worker/mod.rs`, `embed_missing_chunks`: embeds original saved event content only where chunk embedding is absent, then conditionally updates the vector. Embedding provider errors are logged and leave missing vectors; the original evidence remains durable.
- `src/knowledge_store/jobs.rs`, `claim_job` / `finish_job` / `retry_job`: claims available pending or expired jobs with row locks; serializes extraction/consolidation with namespace leases; blocks later extraction behind earlier pending, running or failed jobs; uses 15-minute leases and exponential retry delay capped at 300 seconds. Default maximum attempts is 5 in migration 0003. Failed jobs require explicit retry.
- `src/worker/mod.rs`, `process_with_heartbeat`: renews leases every 30 seconds; lost leases cancel processing. Work traces and terminal results are persisted. The dispatcher is shared infrastructure, shown here because it guarantees the Module 1-to-2 handoff.
- `src/knowledge_store/evidence.rs`, `episode_evidence`: loads namespace-scoped original events via episode_sources ordered by ordinal, returning chunk IDs with role/content/time/metadata.
- `src/worker/extraction.rs`, `extract`: receives the episode-ID job and loads evidence; retries missing source embeddings later in extraction. Existing-assertion snapshots, token windows, claims and entity creation are downstream concerns and are not part of Module 1.

## Example and diagram conventions

Maya's exact E3/E4 messages are the input. `user:maya`, S2 and L4 are illustrative namespace/session/branch values. E3/E4, P2, C3/C4 and J2 abbreviate generated record UUIDs. The actual timestamp uses a complete timestamp rather than the readable date shown. A session external ID is supplied by Pi, not generated by the retain handler.

Arrows between storage cards show data/foreign-key flow, not exact SQL statement execution order. The idempotency gate and all storage writes participate in one transaction. The early-embedding branch is asynchronous and can finish before or after the HTTP response; it is not an acknowledgment dependency. Stored original text refers to content submitted in the request, after Pi has converted messages to text.

No entities, assertions, correction decisions or factual summaries are created at retain time. The same evidence can be read later by Module 2 and by source retrieval.

## Concurrent worker view

The revised view uses UML component symbols, storage cylinders, a durable queue symbol and runtime/storage boundaries. `src/main.rs` reads `MEMORY_WORKER_CONCURRENCY`, defaults to 4, clamps to 1–8, and spawns that many Tokio loops for `extract` and `consolidate`. Every loop calls the shared job-claim function; the claim component is shared code, not a centralized dispatcher process. Namespace leases serialize those inference jobs within a namespace; separate namespaces can progress concurrently. All loops use the shared configured model client. Worker concurrency does not guarantee simultaneous model execution inside Ollama.

An independent worker handles `project`, `rebuild` and `clear_graph`. Early source embedding is separate from this pool and has its own two-permit semaphore. The two worker boxes match the local configured pool size; their job labels are illustrative, not a live scheduling measurement. The diagram's shortened E3 excerpt remains Maya's original evidence; E4 is only summarized as an acknowledgment. Exact messages and detailed validation/recovery behavior remain documented above.

## Configured model specifics

The checked local `.env` selects `EMBEDDING_MODEL=qwen3-embedding-cpu`, `EXTRACTION_MODEL=mem-extractor:general-v1` and `MEMORY_WORKER_CONCURRENCY=2`. The local Ollama `/api/show` response confirms that `qwen3-embedding-cpu` has parent `qwen3-embedding:0.6b`, Q8_0 quantization and `num_gpu 0`. These are configured values, not a claim that a running service was restarted with them. Source defaults remain `qwen3-embedding:0.6b`, `mem-extractor` and four workers.

`src/providers.rs` calls Ollama `/api/embed`, requests 1,024 dimensions and validates vector length. `src/model.rs` calls `/api/generate`. The diagram names Axum at the API boundary, SQLx at the transaction writer, Tokio for the worker tasks, and pgvector for stored embeddings.
